## 第一批：贯通现有能力并修正分镜前置条件

先修正真正影响生成结果和操作路径的问题，前后端采用同一套判断。

### 按制作方式计算需要准备什么

将“文字分镜可以编辑”“可以开始某次生成”“可以导出预演”“可以导出成片”分开。

- 有故事和角色设定即可创建、编辑文字分镜，不要求所有形象、音色和环境图先全部制作完。
- 文字分镜引用稳定的人物和地点身份；具体制作时再绑定所需且有效的资产版本。
  缺素材时明确显示待补内容，不能伪造已确认版本。
- 首帧模式检查有效首帧；首尾帧模式检查两张画面及其依赖。
- 多素材模式检查本次实际选中的图片、视频、音频参考，不再统一要求分镜图。
  按实际渠道约束校验，音频不能在禁止纯音频输入的渠道中孤立提交。
- 提供渠道实际支持的纯文字预演入口，不为它增加图片硬门槛；
  对需要人物一致性的正式片段，清楚提示使用形象参考的价值。
- 模型原声模式不强制先生成独立 TTS。后期配音模式在对应制作和合成节点检查所需录音。
- 报价、提交、批量操作、任务重试、候选选用、预览、导出和失效判断必须一致。
  不能只让按钮可点，而后端仍拦截；也不能后端放行而页面无入口。
- 可用素材只按真实依赖失效，不能因为不相关资产变化要求重做整片。

### 完整传递导演意图和台词

修复文字分镜到视频模型的编译过程，生成内容以当前已保存设计为准。

- 始终从分镜文字取得对白和旁白，不依赖是否已合成音频。
- 明确角色姓名及素材对应关系，区分画内说话、角色画外音、独立旁白。
  不能只把内部角色 ID 交给模型来指代人物。
- 完整组织叙事目的、景别、构图、机位、运镜、空间位置、起始状态、动作与结果、
  台词顺序、声音设计和承接要求；按模式使用相关字段，避免相互矛盾。
- 有实测音频时用实测时长；无音频时使用可解释的预计时长，不能伪装为精确对齐。
- 在模型原声路径编入环境音、音乐需求和禁止项；后期配音路径明确后期混音责任。
- 素材编号必须对应真实上传顺序，用渠道要求的协议表达。
  用户页面呈现“阿茶的形象”“月神的声音”等自然名称，不要求用户写素材标签。
- 生成前的可读摘要要与最终请求同源，显示所选角色、素材用途、台词和声音方式。
  如需要调整生成要求，提供可读的自然语言输入，不新增原始 JSON 或请求体编辑器。

### 增加故事完整性和节奏检查

检查要帮助用户解决创作问题，避免变成一大页技术校验结果。

- 镜头数量默认是建议或预算偏好，允许合理拆分、合并；
  只有用户明确选择固定镜头数量时才进行硬约束。
- 关联故事剧情节点，检查开端、发展、转折和结局的覆盖。
  结构校验通过不能自动视为叙事完整。
- 比较目标时长与镜头、片段、成片实际时长；偏差应展示并能处理。
- 检查台词容量、停顿、动作密度和切镜时机，不能把长对白强塞进几秒钟。
  给出缩短台词、延长片段、拆镜、跨镜延续等可操作建议。
- 预计时长和实测时长分开；产生录音或视频后回填实测结果，提示受影响内容。
- 区分确定不可生成的错误和需要创作者判断的建议。
  不把主观创作建议都做成硬阻塞，也不允许明显缺失内容被虚假标记为完成。

## 第二批：改进分镜、声音和生成片段结构

建立能够承载 H3 能力的最小完整结构，兼容既有单镜作品。

### 分开镜头、生成片段和剪辑采用

三者各自保存职责清楚的数据，并在页面中提供必要的操作。

- 镜头保存导演设计：剧情节点、人物、场景、构图、动作、台词和预计时长。
- 生成片段保存本次生成：覆盖哪些相邻镜头、各镜时间范围、切镜计划、
  制作方式、参考资产版本、声音方式、生成参数和输出候选。
- 剪辑采用保存最终选择：使用哪个片段版本、使用其中哪段时间。
- 默认兼容一段一镜，支持将相邻镜头组成一个生成片段，以及取消组合、重新拆分。
  不仅增加数据库字段，还要让用户可以在页面完成这些操作。
- 单镜连续运镜、片段内切镜、首尾帧过渡要分清，避免提示词同时要求互相冲突的结果。
- 一个生成视频被多个镜头采用时，正确处理时间区间，不能在导出中重复拼接整段视频。
- 设计时间与实际生成时间可能有偏差，应允许回放后调整采用区间；
  不声称提示词时间码必然被模型逐帧执行。
- 存量镜头、候选和输出需要安全兼容；迁移保留历史，不默认覆盖或重新生成。

### 完善声音和跨镜对白

将“谁发声”“是否出现在画面里”“使用哪种声音”分开表达。

- 支持可见人物、画外发言角色、独立叙述者；画外角色不应被强制加入画面。
- 台词保留稳定身份，支持跨切镜延续和画内、画外转换，避免拆成重复对白。
- 区分音色参考、指定录音复用、模型生成对白、后期配音、环境音和配乐。
- 模型原声在页面可直接试听实际视频音轨；后期不能再重复混入同一句独立配音。
- 角色连听与声音一致性检查应覆盖当前实际采用的声音，包括原生视频声音。
- 独立配音按实测录音安排画面和口型；“静音视频加配音”不能标记为已完成口型同步。
- 跨镜声音在最终剪辑中不能重复、突然中断或出现不自然的接缝。
- 字幕对应实际采用的对白及时间，不凭文字生成就宣布自动精准对齐。

### 把实际参考素材变为明确的制作输入

保留角色和场景参考库，增加本次生成真正使用的素材清单。

- 按片段内容和制作方式建议已有素材，允许用户更换、移除和补充。
- 以缩略图、音频试听和视频预览展示素材，标明身份、场景、动作、构图、声音等用途。
- 区分“项目已有”“建议用于本次”“已选用于本次”，并让请求确实携带已选内容。
- 角色正面、侧面、三视图与服装变体按需要使用，不能无差别全塞入请求。
- 变更参考、台词或动作后，精确提示哪些候选与生成片段需要更新。
- 保留已付费候选与原片追溯；生成中的旧结果不得覆盖用户后续编辑或已选版本。
- 有效分镜候选可按现有逻辑自动应用，历史方案可切换；
  不完整结果先通过可读的问题提示处理，不将 JSON 修复工作交给普通用户。

### 统一渠道能力与参数

模型能力、第三方渠道接口和工作台支持范围必须分别核实。

- 阅读手册，同时核对当前真实使用的渠道、模型版本和接口支持。
  不能把手册 4–15 秒直接硬覆盖现有渠道，也不能把适配器 4–30 秒视为已验证的通用事实。
- 统一时长、分辨率、画幅、素材数量、文件大小、音视频参考时长和请求大小约束，
  覆盖前端选择、后端校验、费用估算和任务提交。
- 文字镜头时长可表达叙事需求，实际生成片段必须符合渠道能力。
  超出范围时提供拆分或调整的页面路径。
- 对未支持的组合给出准确、可操作的中文说明。
  不能展示一个可用开关，提交后才发现从未接入，也不能用假成功代替缺失能力。

## 第三批：定向返修、成片状态与完整制作体验

沿用候选、版本和选用机制，把修改后的结果完整接回项目。

- 增加基于当前或历史原视频进行定向修改的入口：修改台词、表演、角色、环境或局部细节。
- 让用户说明“要改什么”“保留什么”，按需选择参考录音、图片或视频。
  复用现有生成与报价机制；实际支持时走视频编辑或参考视频生成路径。
- 保留原片，修改结果作为新候选，支持对比、试听、选用和恢复历史版本。
  不保证模型会毫无偏差地保留其他内容，必须回放验收。
- 保留本地修正版导入，并明确区分“导入现有修正版”和“调用模型修改”。
  本地上传功能不能冒充已经实现了模型编辑。
- 定向修改结果要重新参与选用、依赖检查、时间线、预览和导出。
- 阶段状态区分：方案可编辑、参考待补、可生成、生成中、候选待选、
  待回放检查、可导出成片。只保留用户有用的层级，不机械堆放所有内部状态。
- 分镜确认、媒体完成、内容验收和导出完成分别判断。
  没有视频时不能提示成片已就绪；可导出预演不能被表述为正式成片已完成。
- 保留本地媒体正常浏览、合成和导出能力。
  导出尽量保留原素材分辨率、正常播放速度和完整内容；
  裁切、加速、补尾帧或其他时长处理需有明确产品选择，不能偷偷用来凑目标时长。

## 前端排版、视觉和用户语言要求

界面必须服务创作决策，不能把后端结构直接铺成表单。

1. 保留熟悉的顶部和左侧导航，复用现有色彩、字体、间距、圆角与组件风格。
   统一内容区对齐、留白、标题层级与按钮主次，不随意增加炫光、装饰或无关卡片。
2. 分镜区提供可用的分镜表、故事板与时间轴视图，切换后选择与编辑状态保持一致。
   没有图片时，卡片仍能显示剧情目的、动作、台词、预计时长和下一步，避免整页大占位框。
3. 详情区突出“本段内容、制作方式、本次参考、台词与声音、生成与版本”。
   常用操作直达，复杂参数按需展开，避免一个弹窗里塞满所有设置。
4. 输入方式与声音方式分别选择；根据选择显示必要区域。
   不再把“1 画面、2 声音、3 视频”当作所有模式都必须遵守的制作顺序。
5. 页面只显示有意义的名称、状态、可预览的素材、费用、进度和可执行的问题处理方式。
   不显示原始 JSON、schema、payload、内部 ID、指纹、任务协议、技术测试记录。
6. 保持按钮和表单可读、点击目标足够大、键盘焦点清楚。
   弹窗、滚动区、底部操作条和时间线不能互相遮挡，长中文和错误提示能正常换行。
7. 检查常用桌面宽度，例如 1280、1440、1920，以及窄屏下的可用性。
   窄屏可以调整布局或提供诚实的使用提示，不能依靠裁掉内容隐藏问题。
8. 实际在浏览器查看每个受影响阶段，检查正常、空态、加载、失败、待选和完成状态。
   使用截图、实际尺寸与计算样式定位问题，不能只凭组件代码或 typecheck 判断排版完成。
9. 保存、确认、生成、选用、退回修改的操作要有清楚反馈。
   刷新和切换阶段后继续保持真实状态，避免保存后消失、候选选用失败或死循环导航。

## 改动完成后：通过页面跑完《忘忧茶》

这是最终验收的核心约束。产品操作必须发生在普通用户使用的页面上，
并且刷新后仍能在页面看到真实结果。

允许通过命令行修改代码、启动正常服务、运行开发测试、查看日志、
读取数据库诊断和检查导出文件，但以下行为不能替代闭环验收：

- 直接调用生成接口或供应商接口，事后把结果写进项目。
- 用脚本补状态、改数据库、伪造候选、绕过前置检查或强制确认。
- 手工在后台拼接成片，然后声称工作台导出成功。
- 只证明接口能跑，或者只看页面截图，而没有实际生成、选用、试听和播放。
- 使用只有代理才能执行的隐藏路径，使普通用户无法在页面复现。

正常页面触发后端任务、worker、模型调用与合成属于正确流程。
浏览器自动化可以操作同样的可见控件；不能通过注入内部状态或接口写入走捷径。
发现页面缺入口或走不通时，先补好产品，再回到该步骤通过页面继续完成。

按以下顺序完成实际项目：

1. 在页面打开原有《忘忧茶》，检查当前故事、人物、音色、环境、分镜和候选。
   核对项目身份，保留并优先复用已选且有效的素材。
2. 统一故事中的人物名称与当前已确认人物，延续现有题材、视觉风格和核心主题。
   补足转折与结局，明确本次完成的是完整短片；不能把只有开场的16秒当作原30秒故事完成。
3. 通过页面完善镜头、台词与时间安排，处理长台词和目标时长差异。
   可合理缩写对白、补镜或调整分段，不用机械加速和冻结画面凑时长。
4. 按镜头需求选择制作方式和声音方式。补齐确实缺少的参考素材，
   通过页面生成或上传、预览、选用和确认，不重新制作所有已有角色和环境。
5. 至少实测一条适合本片的“多素材参考、无需先生成本镜分镜图”的真实生成路径。
   针对有对白的片段，验证模型原声路径无需先做独立 TTS，也会传递正确台词；
   检查实际说话内容、说话人、音色和口型。其他路径用适当测试覆盖，不为了测试重复消耗整片素材。
6. 为适合连贯表演的相邻镜头实际使用一次多镜头生成片段，
   在页面核对切镜、跨镜对白和采用区间。若渠道不支持，明确实际限制并完成能力适配；
   未能真实验证的能力列为未完成，不能仅凭数据结构或演示界面声称已交付。
7. 每次生成经页面查看费用和参数，提交后从任务和候选页面跟进。
   使用已有额度完成必要生成，避免重复付费和无上限重试。
   不擅自充值、购买套餐或改变账户。余额、登录或服务故障无法自行解决时准确报告阻塞。
8. 逐段播放并试听候选，选择合格版本。检查人物身份、服饰、环境、空间位置、动作结果、
   台词内容、发言人、音色、口型和邻镜承接。对实际发现的问题使用页面返修流程，
   验证新候选、对比选用、历史保留与后续导出的完整链路。
9. 在页面完成全片预览，检查剧情从开端到结局成立，节奏自然，
   语句未截断，原声与后期声音未重复，字幕准确可读，衔接无明显断裂。
   技术可播放与内容质量合格分别检查，不能互相代替。
10. 通过页面发起最终导出，等待真正完成，再通过页面播放并下载最终 MP4。
    检查时长、画幅、分辨率、声音与字幕；文件应完整可播放，且与当前选中版本一致。
11. 刷新页面并重新进入该项目，确认角色素材、分镜、片段、候选选中状态、
    制作进度、预览与导出记录都能恢复。用户接手后能找到并继续编辑、重新生成或再次导出。
12. 最终把页面停留在《忘忧茶》成片预览或导出结果，交付可访问的成片文件及项目入口。

开发测试可以使用隔离的夹具和临时数据，但不能把测试素材或工程记录塞进真实作品界面。
完成真实项目的生成与返修属于用户本次已授权的任务，不要每到正常制作步骤就反复请求批准。
需要用户处理的真实外部限制与普通实现选择必须分清。

## 开发验证与完成标准

测试应验证关键行为，不只重复实现细节，也不以静态检查代替真实页面流程。

实施前记录现有失败，实施后运行与改动相关的前后端测试、类型检查和构建。
不要为了交差忽略失败、删除测试或放宽关键断言。
与本次相关的旧失败应修复；不相关失败清楚说明实际影响。
重点覆盖以下回归：

- 无分镜图片但联合参考完备时，前后端判断一致，可正常报价和生成。
- 模型原声、无独立配音时，最终请求仍包含正确对白、旁白和声音要求。
- 纯文字分镜可提前编辑；正式制作不会使用缺失、错误或过期的资产版本。
- 固定镜头数与推荐镜头数区别正确，故事覆盖、时长偏差和台词容量提示有效。
- 画外角色与跨镜台词正确，原声不被重复混音，字幕与实际采用内容一致。
- 一段多镜和采用区间正确，导出不重复片段，不误截断对白或改变速度。
- 资产更新仅影响真实依赖，历史候选和付费成果不丢失，生成不会覆盖后续人工编辑。
- 不完整分镜的恢复、有效候选自动应用、历史切换和刷新恢复不回退。
- 视频返修、选择候选、全片预览、最终导出都可在页面完成。
- 错误提示与状态真实，所有新增控件有实际功能，产品页面没有工程调试内容。

保存必要的页面截图和精简验收记录到开发文档目录即可。
不要为了显得工作完整新增大量重复 JSON、测试报表或产品内技术面板。
没有真实调用、试听或播放的内容必须标为未验证，不能写成通过。

最终交付说明使用中文，清楚列出：

1. 改动前的基线提交哈希，以及最后的 Git 状态；默认未推送。
2. 已完成的工作流、数据结构、模型接入与前端改动，重要文件和迁移说明。
3. 前后端验证和页面验证的实际结果，以及仍存在的限制。
4. 《忘忧茶》从已有素材继续完成的具体页面操作路径。
5. 通过页面完成的真实生成、选用、返修、预览与导出结果。
6. 最终成片路径、时长、画幅、分辨率、实际声音方式和回放检查结论。
7. 关键页面截图，并说明刷新后如何找到和继续操作这个项目。

只有代码、页面操作和真实成片全部形成闭环，才能宣布本次任务完成。
若外部条件阻塞，完成其余可独立推进的工作，并明确列出未完成步骤及恢复条件；
不能把未完成的闭环包装成成功。
