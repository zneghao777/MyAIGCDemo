# AI 短剧生成工作台 — 架构设计方案

## 一、产品全景

```
一句话创意
   │
   ▼
┌─────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌─────────────┐
│ ① 创意输入   │──▶│ ② LLM 生成分 │──▶│ ③ 每分镜生成 │──▶│ ④ 视频模型   │──▶│ ⑤ 拼接导出  │
│  (工作台)    │   │  镜剧本 JSON │   │  首帧图片    │   │  图生视频 API │   │  ffmpeg     │
└─────────────┘   └──────────────┘   └──────────────┘   └──────────────┘   └─────────────┘
                         ▲                                                            ▲
                         │                                                            │
                  ┌──────┴───────────────────────────────────────────────────┐      │
                  │              3D 导演台 (场景摆位 / 人物走位 / 机位)        │──────┘
                  │        轨迹与摆位信息反哺分镜 prompt / 控制信号           │
                  └──────────────────────────────────────────────────────────┘
```

核心思路：**3D 导演台不是替代 AI 生成，而是作为"导演意图的载体"**——用户在 3D 空间里摆场景、定走位、设机位，这些结构化信息被转换成更精准的 prompt / 控制信号，喂给图片与视频模型，大幅提升生成结果的确定性和可控性。

## 二、总体架构

```
┌────────────────────────── 前端工作台 (Next.js) ──────────────────────────┐
│  创意输入页 │ 剧本/分镜编辑器 │ 3D导演台(React Three Fiber) │ 时间线 │ 导出页 │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ REST / SSE(流式) / WebSocket(任务进度)
┌──────────────────────────────────▼───────────────────────────────────────┐
│                          后端服务 (NestJS / FastAPI)                       │
│  ┌─────────┐ ┌─────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────────┐  │
│  │ 剧本编排 │ │ 图片生成 │ │ 视频生成  │ │ 任务编排  │ │ 合成导出(ffmpeg) │  │
│  │ Service │ │ Service │ │ Service  │ │ (队列)    │ │                  │  │
│  └────┬────┘ └────┬────┘ └────┬─────┘ └────┬─────┘ └────────┬─────────┘  │
└───────┼───────────┼───────────┼────────────┼─────────────────┼────────────┘
        ▼           ▼           ▼            ▼                 ▼
     LLM API     文生图 API   视频模型 API   Redis 队列       ffmpeg/GPU
   (结构化输出)  (角色一致性)  (图生视频)    (BullMQ/Celery)  (拼接/字幕/配音)
```

## 三、核心数据模型

```typescript
Project {
  id, name, stylePreset,        // 全局风格锁定
  characters: Character[],      // 角色设定卡(外观、服装、LoRA/参考图)
  scenes: Scene[]
}

Character {
  id, name, description,
  referenceImages[],            // 角色三视图/参考图 → 保证一致性
  voiceId                       // TTS 音色
}

Scene {  // 一个分镜节点
  id, index,                    // 镜号
  shotType,                     // 景别: 远/全/中/近/特写
  cameraMove,                   // 运镜: 推/拉/摇/移/跟/固定
  durationSec,
  imagePrompt, videoPrompt,     // AI 生成 + 用户可编辑
  dialogue, narration,          // 台词/旁白 → TTS
  firstFrameImage,              // 首帧图(文生图产物)
  videoUrl,                     // 视频产物
  directorData: {               // ★ 3D 导演台产物
    sceneLayout: JSON,          // 场景摆位(道具/家具坐标)
    actorTracks: [              // 人物走位关键帧
      { actorId, keyframes: [{ t, position, rotation, action }] }
    ],
    cameraTrack: {              // 机位关键帧(位置/朝向/焦距)
      keyframes: [{ t, position, lookAt, fov }]
    }
  },
  status: 'draft'|'image_pending'|'video_pending'|'done'|'failed'
}
```

## 四、五大模块设计

### 模块 1：创意 → 分镜剧本（LLM 结构化生成）

- **输入**：一句话创意 + 可选参数（时长、风格、集数、角色数）
- **两段式生成**（效果好于一次生成）：
  1. 先让 LLM 扩写成短剧本大纲（故事、角色小传、分场）
  2. 再按 Scene JSON Schema 逐场拆分镜（每镜含景别/运镜/画面描述/台词）
- **技术要点**：
  - 使用支持 Structured Output 的模型（GPT-4o / Claude / DeepSeek 等），用 JSON Schema 约束输出
  - Prompt 中内置"导演知识"：镜头语言模板（如"从特写手部拉远至全景"）、节奏模板（冲突-转折-高潮）
  - 生成结果必须**可编辑**（卡片式分镜编辑器），用户微调后再进入后续流程
- **风格锁定**：全项目维护一份 style prompt 前缀 + 负面词，注入每个分镜的图片 prompt

### 模块 2：分镜 → 首帧图片（解决角色一致性）

- 基础：文生图 API（即梦/Midjourney/Flux/SD3 等）
- **一致性是最大难点**，按成本递进的方案：
  1. 参考图模式：角色设定图作为 image reference 输入（即梦"参考生图"、Flux Kontext、Nano Banana 均支持）
  2. 训练 LoRA：每个角色训练专属 LoRA（Flux/SD 生态），一致性最好
  3. 首帧链式约束：后续分镜以前一镜尾帧/场景图为参考
- 若使用 3D 导演台：可将 3D 场景**渲染成低保真布局图（layout/深度图/线稿）** 作为图生图的参考，控制构图

### 模块 3：图片 → 视频片段（图生视频 API）

- **模式**：image-to-video（首帧驱动，比纯文生视频可控得多）
- **候选 API**（均提供异步任务接口）：

| 服务 | 特点 | 备注 |
|---|---|---|
| 可灵 Kling | 运镜控制好、动作自然 | 首选，支持首尾帧 |
| 即梦/豆包 | 与即梦图片生态打通、性价比高 | |
| Vidu | 参考生视频、角色一致性好 | 多主体参考 |
| Runway Gen-4 / Veo | 质量高、价格贵 | 海外项目 |

- **工程要点**：
  - 所有视频任务走**异步队列**（BullMQ），任务提交 → 轮询/webhook 回调 → 下载落盘
  - 限流与重试：视频 API 通常并发限制 1~3，需要队列排队 + 指数退避重试
  - 运镜指令映射：`cameraMove` 字段映射为各 API 的 camera_control 参数（如 Kling 的 `camera.moveDirection`）
  - 单镜时长 5~10s，不足则分段生成或后期变速
- **导演台增强**：若用户在 3D 台定义了走位/运镜轨迹，可以将轨迹翻译为自然语言运镜描述注入 video prompt（"镜头跟随人物向左横移，缓慢推近"），或渲染深度序列做控制信号

### 模块 4：拼接导出（合成管线）

ffmpeg 流水线：

```
各分镜视频 ──▶ 统一转码(分辨率/帧率/时长对齐)
          ──▶ 转场(xfade: 硬切/叠化/黑场)
          ──▶ TTS 配音(台词→语音，按时间轴对位)
          ──▶ 字幕烧录(dialogue → ASS/SRT)
          ──▶ BGM 混音(amix + 自动闪避 ducking)
          ──▶ 封面(取首镜首帧) + MP4 导出
```

- TTS：火山引擎 / Minimax / ElevenLabs，每角色绑定音色
- **对齐问题**：视频片段长度 ≠ 台词 TTS 时长 → 需要垫片（定格/慢放）或裁剪策略
- 导出可配置：分辨率(720p/1080p 竖屏)、水印、字幕开关

### 模块 5：3D 导演台（React Three Fiber）

这是差异化功能，定位是"**给 AI 的可视化导演指令**"：

**场景摆位**
- 简单场景模板库：房间、街道、办公室、户外（用占位几何体 + 灰盒模型，不需要精细资产）
- 拖拽摆放道具/家具（`@react-three/drei` 的 TransformControls + raycasting）
- 网格吸附、旋转缩放

**人物走位**
- 人物用简单人形代理（胶囊 + 朝向箭头，可接 Mixamo 低模）
- **关键帧时间轴**：底部时间轴上为每个人物添加关键帧（位置 + 朝向 + 动作标签：走/跑/坐/拥抱）
- 播放预览：按关键帧插值（lerp + CatmullRom 曲线路径）实时预演走位

**机位设置**
- 虚拟摄像机（Gizmo 手柄操控），同样支持关键帧 → 生成推拉摇移轨迹
- 实时预览取景框（子视口显示当前机位画面）
- 机位 + 景别自动联动分镜的 `shotType`/`cameraMove` 字段

**数据流向**
```
3D 导演台 ──序列化──▶ directorData (JSON) ──▶ 
  ① 自动生成/增强 imagePrompt(构图描述) 
  ② 渲染布局参考图/深度图 → 图生图参考
  ③ 轨迹翻译成运镜指令 → 视频 API camera 参数
```

## 五、技术选型汇总

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Next.js 14 + TypeScript | 生态成熟、SSE 友好 |
| 状态管理 | Zustand + Immer | 项目数据树状、需频繁局部更新 |
| 3D | React Three Fiber + drei | 声明式 Three.js，与 React 无缝 |
| 时间线/关键帧 | 自研（HTML canvas）或借鉴 xstate | 走位关键帧核心交互 |
| 后端 | NestJS (Node) 或 FastAPI (Python) | Node 全栈统一；Python 方便后续自托管 SD/ffmpeg 深度处理 |
| 任务队列 | Redis + BullMQ / Celery | 图片视频任务都是长耗时异步 |
| 数据库 | PostgreSQL (JSONB 存 directorData) + 对象存储 S3/OSS | |
| 流式/进度 | SSE（剧本流式生成）+ WebSocket（任务进度推送） | |
| 媒体处理 | ffmpeg（服务端）| 拼接/转场/字幕/混音一站式 |

## 六、关键工程难点与对策

1. **角色一致性**（最影响成片质量）：参考图 + LoRA + 全局风格前缀三件套；在 UI 上强制"先建角色卡，再生成分镜"
2. **视频 API 的不确定性**：耗时 1~5 分钟/镜、可能失败或内容不符 → 队列重试 + 生成多候选取优 + 人工换镜头重生成
3. **音画对齐**：先 TTS 定长，再让视频时长匹配（Kling 支持首尾帧可做"延展"）；提供"以音频为准"的对齐模式
4. **成本控制**：分镜粒度预估 token/张数/秒数，生成前给出报价预览；草稿用低档模型，定稿用高档
5. **3D 台的学习成本**：提供"AI 自动摆位"（LLM 根据 scene 描述生成初始 directorData），用户只需微调

## 七、分期落地路线

**Phase 1 — MVP（4~6 周）**
- 创意输入 → LLM 分镜 JSON → 卡片式分镜编辑器
- 每镜文生图（接 1 个图片 API + 参考图一致性）
- 图生视频（接 Kling/即梦）+ 异步任务队列 + 进度推送
- ffmpeg 拼接导出（硬切 + 字幕 + TTS）
- ✅ 验证：端到端能出一条 60s 短片

**Phase 2 — 3D 导演台基础（4 周）**
- 场景模板 + 拖拽摆位 + 虚拟机位
- directorData 序列化 → prompt 增强（构图/运镜描述自动注入）
- 布局参考图渲染 → 图生图参考

**Phase 3 — 走位与轨迹（4 周）**
- 人物代理 + 关键帧时间轴 + 路径动画预演
- 轨迹 → 运镜指令映射 → 视频 API camera 参数
- 音画对齐优化、多候选取优

**Phase 4 — 体验完善（持续）**
- 角色 LoRA 训练流水线、多集管理、模板市场、协作
