# CineAI Studio 角色资产创作流程

本次改造在现有 Next.js、Zustand、FastAPI、SQLAlchemy、Alembic、PostgreSQL、
Celery、Redis、DeepSeek、MiniMax、图片服务、COS 和 ffmpeg 管线上实现。
视频生成模型保持关闭，输出名称为“分镜动态预演成片”。
本文中的新流程约定优先于原 Phase B1 中直接生成分镜、整镜单音色的约定。

## 用户流程

在新建页输入一句创意并创建项目。创建操作不调用模型。

1. 在故事方案页生成完整候选，查看标题、梗概、主题、起承转合、结局、时长、
   画幅、风格、人物关系和场景。选用后可以编辑，再确认故事与角色方案。
2. 在角色资产页生成或上传主参考图、试听并选择声音，保存角色版本并定稿。
   需要补充参考时，以已选主图生成；不要把随机独立图标称为同一个稳定角色。
   全局库保存固定角色版本，复用时复制媒体，不会随原项目修改而变化。
3. 确认所有角色后生成分镜草案。每镜绑定角色 ID、已确认角色版本和场景 ID；
   每句台词有独立发言人、情绪、语速倍率、句后停顿。旁白使用独立配置。
   确认分镜后，可按镜生成，也可批量生成缺失或过期的资产。
4. 所有结果先进入候选。选用画面和配音后，合成前检查通过才能导出。
   预览后仍可修改单句、音色、镜头和导演台数据，再生成受影响部分。

模型调用前展示范围、调用次数上界和费用估算。无完整单价时显示“无法估算”，
不把零值称为免费。新一轮随机候选由“重新生成”显式触发；普通重复提交去重。
生成失败及取消都持久化，刷新不发起新的生成请求。

## 数据关系

现有业务表继续承担主业务，不建立第二套项目或任务系统。

| 位置 | 内容 |
| --- | --- |
| `project.creative` | 草稿版本、方案、三个确认状态、当前阶段、独立旁白配置 |
| `character.creative` | Persona、已选主图、补充参考、声音、定稿标记、固定版本 ID |
| `scene.creative` | Shot、角色版本映射、逐句台词和旁白、选中画面与音频段 |
| `creative_revision` | 不可变的项目、角色、分镜完整状态快照 |
| `creative_candidate` | 输入指纹、任务 ID、候选内容、媒体键、降级信息 |
| `library_character` | 固定的可复用角色版本，拥有独立媒体副本 |
| `task.payload.creative` | 操作类型、输入快照、目标、生成参数及抽取标识 |
| `export_job.settings.manifest` | 本次成片使用的项目版本及全部分镜状态快照 |

分镜的 `cast` 为角色 ID 到角色版本 ID 的映射。版本必须属于本项目并已定稿。
造型引用为该角色版本中的命名变体。主图/补充图是实际 COS 资产，非展示占位图。
台词没有“解析姓名前缀”路径，也不再取项目第一个角色的音色。

`0003_creative_flow.py` 只增加可空 JSONB 字段和三张表，不回填付费资产。
旧项目保持原样；用户显式开启新流程后，把原文本保留为待绑定的旧台词。
原媒体仍可访问。旧项目已保存的配音可继续合成；缺少语音时要求明确绑定发言人，
不在后台猜测声音。新版项目暂不提供一键整项目复制，改为新建并复用角色库版本。

## 版本、失效与任务

编辑请求携带 `expected`，导演台携带 `expectedVersion`。过期编辑返回 409。
生成任务读取提交时的快照，只新增候选；不能直接覆盖用户当前草稿和选中资产。
选用时再次计算输入指纹，旧输入候选保留但不能替换当前内容。

| 修改 | 受影响范围 |
| --- | --- |
| 角色外貌、人设或主参考图 | 主图需要重新确认；相关分镜画面、成片过期 |
| 角色声音或基础语速 | 对应发言人的音频、时间线、成片；画面可复用 |
| 单句文本、情绪、速度、停顿 | 该句音频及本镜音频候选、字幕、镜长；画面可复用 |
| 分镜动作、构图、场景、导演台 | 本镜画面与导出结果；配音按内容复用 |
| 删除全部台词和旁白 | 当前音轨置空；旧音频仍保留在历史中 |
| BGM 或导出设置 | 重新混音和导出，不调用文本、图片或声音模型 |

角色本地定稿后，明确更新引用该角色的镜头版本；比较的是视觉和声音各自的依赖，
不会因角色声音版本变化而重画画面。全局角色库每次存入均产生固定版本，
不传播修改到已复用的项目。

分镜重新生成和手动归档保留原 Scene 行、任务、版本及媒体。旧镜头以负序号归档，
活动列表仅查询非负序号。归档历史可在版本记录中追溯，不自动删除 COS 文件。

复用现有数据库任务出站记录、项目锁、Redis 执行锁和 Celery 队列。
新版生成任务遇到不明确的外部失败不自动付费重试；用户可在队列明确重试。
每句成功配音立即保存为可复用记录，后续句子失败后重试不重复合成已保存句子。
外部服务没有通用幂等协议：若服务端已收费但网络在返回结果前中断，本地无法
证明该次收费或找回结果，页面明确提示后由用户决定是否重试。
结构化 LLM 输出不合法时仍允许一次修复调用，费用估算应视为范围估算。

## 图片、声音与媒体

图片输入组合项目风格、场景、人物版本、参考图编号、造型、动作、表情、构图、
景别和导演台数据。`IMAGE_MAX_REFERENCES` 默认 2；超出部分只提供文本约束，
候选与任务日志显示降级。服务商明确不支持参考图接口时记录降级，不承诺一致性。
外貌稳定、表演效果是人工预览事项，未实现自动视觉审核。

MiniMax 两条路径分别展示和保存来源：

- **AI 设计音色**：`POST /v1/voice_design`，请求包含 `prompt`、
  `preview_text`、稳定的自定义 `voice_id`，解析返回的 `voice_id` 和 hex
  `trial_audio`。错误不转换成普通 TTS 的“设计成功”。
- **匹配预设音色**：`POST /v1/get_voice` 查询当前账号真实目录，DeepSeek 根据
  角色声音描述匹配最多三个合法预设 ID，再由用户生成试听并选择。
- **逐句 TTS**：`POST /v1/t2a_v2`，发言人选中音色加单句情绪、语速。
  角色基础语速乘以单句倍率并约束在 0.5–2。句后停顿由本地媒体管线精确插入。

官方依据：[音色设计](https://platform.minimax.cn/docs/api-reference/voice-design-design)、
[音色目录](https://platform.minimax.cn/docs/api-reference/voice-management-get)、
[同步 TTS](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)。
音色设计可能涉及试听及后续首次使用费用；当前未配置完整价格，不提供虚假报价。

音频使用 ffprobe 实测长度。台词按数组顺序排列，随后播放独立旁白。
媒体管线将每段规范到实测时长与句后停顿，生成对应字幕区间；镜长取预计镜长
与音轨总长加尾垫的较大值，避免截断。当前字幕是逐句时间戳，不声称逐字对齐。
音效说明仅保留在分镜中，本次不自动生成环境音效。
导出页支持上传最多 20 MB / 10 分钟的 BGM，规范为 MP3 并保存 COS；
选择的 BGM 资产写入导出设置，只重新混音。缺少曲风素材时拒绝导出并提示上传，
不再静默跳过并声称混音完成。

导出完全复用已确认素材，不隐式调用 TTS。导出快照独立于后续编辑，
历史导出页面显示过期状态及 manifest，重新混音不覆盖旧成片。

## 启动与配置

继续使用本机既有 PostgreSQL 和 Redis，不新增数据库容器。
配置优先级：`.env.example` → `.env` → `.env.local` → 进程环境变量。
第三方密钥只由 Python 后端加载，不进入 `NEXT_PUBLIC_*`。

```bash
# 仓库根目录
uv sync --project backend
backend/.venv/bin/python backend/scripts/check_config.py
backend/.venv/bin/python backend/scripts/dev.py
# 另一个终端
npm run dev
```

启动器先执行 Alembic，再启动 API、五个 Worker 队列和 Beat。
macOS 每队列使用 solo 单进程，避开线程间共享异步数据库引擎的事件循环问题；
Linux 保留 prefork。不同类型队列仍相互独立。
若已运行旧 CineAI 服务，先停止其启动器，再启动新版；不要停止共享数据库。
SSE 已在进入长连接前释放数据库事务，避免阻塞后续结构迁移。

新接口以 `/api/creative` 为前缀，沿用原项目、任务、资产与导出接口。
`/api/creative/projects/{id}` 一次读取阶段、候选、版本、过期状态与检查结果。
API 文档可在 [本机 Swagger](http://127.0.0.1:8000/docs) 查看。

## 自动化与实际验证

Fake Provider 用于关系与状态验证，ffmpeg 使用实际二进制。执行：

```bash
cd backend
.venv/bin/python -m pytest -q
.venv/bin/ruff check app tests scripts --select F
# 仓库根目录
npm run typecheck
npm run build
```

测试只重建 `cineai_test`，Redis 使用数据库 5；生产使用 `cineai` 和 Redis 数据库 4。
新测试覆盖角色版本、两名发言人、独立旁白、精确停顿、逐句复用、音色失效传播、
外貌草稿失效、候选旧任务、防重复、取消、刷新状态、旧项目兼容、全局固定版本、
部分配音失败恢复、删除最后一句、导演台引用和实际 MP4 合成。
