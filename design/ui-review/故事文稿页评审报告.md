# 故事文稿页 · 实机渲染评审报告

- **评审对象**：`/studio?stage=plan`（阶段 01 故事文稿）
- **评审方式**：Chrome 实机渲染 + 几何探针 + 计算样式读取（非源码推导）
- **视口**：1080×685（主）、1440×900、1280×800
- **数据**：项目 `界面验收测试 · 保存与确认`（含完整 4 段故事梗概 + 人物初稿）
- **被推翻的假设**：① 底栏遮挡正文 —— 不成立，主区 `padding-bottom:112px` > 底栏 78px，几何测量无重叠；② 文本被截断 —— 不成立，`field-sizing:content` 生效，全部 textarea `scrollHeight == clientHeight`

## 总评 5.8 / 10

页面的**内容组织是成熟的**（左文稿 / 右设定 / 底栏保存的三段式，职责清晰，5阶段流程可追溯）。
但**视觉一致性是明显短板**：同一个页面内并存三套控件样式、两套标签规范，且有一套 CSS 声明被另一套完全覆盖导致设计意图失效。
问题不在"没设计"，而在"两套设计打架"。

| 维度 | 评分 | 一句话 |
| --- | --- | --- |
| 信息架构 | 7.0 | 三段式职责清晰，5 步流程可追溯 |

## P0 · 必修

### P0-1 聚焦时整段文字横向跳动 12px

`workbench.css:164-168`

```css
.creative-workbench .cw-manuscript :is(input, textarea):focus {
  padding-left: 12px;   /* 未聚焦态是 0 */
}
```

实测（`padding-left` before → after）：

| 状态 | padding-left | 背景 |
| --- | --- | --- |
| 未聚焦 | `0px` | `rgb(22,29,37)` |
| 聚焦 | `12px` | `rgb(22,29,37)` |

textarea 是定宽 + `field-sizing:content`，多出的 12px 内边距会让**每一行文字重新折行**。
点击输入框的瞬间，整段梗概向右重排一行 — 见 `shots/06-focus.png`，与 `02-after-enter.png` 对比肉眼可见。
这是编辑场景里最敏感的一类抖动：用户正准备读/改这段文字。

**修**：`textarea` 用 `box-shadow` / `outline` 表达聚焦，不要动 `padding`。若坚持要内缩，
用 `text-indent` 配合 `transition`，或只对单行 `input` 生效。

---

### P0-2 文稿区的"下划线编辑感"设计完全失效

`workbench.css:154-163` 明确声明了一套极简编辑器样式：

```css
.creative-workbench .cw-manuscript :is(input, textarea) {
  background: transparent;
  border: 1px solid transparent;
  border-bottom-color: #282d38;   /* 只要一条下边线 */
  border-radius: 0;
  padding: 10px 0;
  font-size: 16px;
}
```

但 `globals.css:4999` 的 `.creative-page textarea`  specificity 更高、且在后：

```css
.creative-page textarea { background:#20242f; border:1px solid #3b4050; border-radius:6px; }
```

实测落值：`background: rgb(22,29,37)`、`border: 1px`、`border-radius: 0px`。
**背景和四边框都在，只有 `border-radius` 因为 `cinema.module.css:402-406` 覆盖成 0 而幸存。**
结果是"要下划线"变成了"带圆角矩形框"，截图里每个梗概/段落都是一个明显的方块。

顺带：声明的 `font-size:16px` 也被 `globals.css:4999` 的 `font:inherit` 压回 14px。

**修**：给文稿区一个更明确的容器作用域（`.cw-manuscript textarea`）提到 globals 之前，
或反过来在 `globals.css` 的 `.creative-page textarea` 后补一条显式覆盖。
现在的写法下，这段 CSS 里有4 条声明是死代码。

---

### P0-3 同页三套控件圆角，表单直角与圆角混用

实测落值：

| 控件 | border-radius | 来源 |
| --- | --- | --- |
| 文稿区 textarea | **0px** | `cinema.module.css:404` |
| 文稿区 片名 input | **0px** | `cinema.module.css:411` |
| 设定区 select / number / textarea | **6px** | `globals.css:4999` |
| 底部/标题按钮 | 7px | DESIGN.md 规范 |
| 卡片 | 9px | DESIGN.md 规范 |

视觉后果（`shots/02-after-enter.png`）：左侧文稿区是**直角、无线框**，
右侧设定区是**圆角、带框**，中间一条竖线分隔。同屏出现两套表单语言，
用户会下意识认为"这两类东西不是同一种东西" — 但它们都是需要编辑的输入框。

**修**：要么文稿区跟着走 6px 圆角（承认它就是表单），
要么设定区也走直角（承认文稿区就是编辑区）。**不能两套并存**。
DESIGN.md 只规定了按钮 7px / 卡片 9px，表单圆角本身没写，
建议在规范里补一条再执行。

## P1 · 建议修

### P1-1 两套标签规范，中文标签被 `letter-spacing` 撑散

实测对照：

| | 文稿区 label | 设定区 label |
| --- | --- | --- |
| 字号 | 12px | 12px |
| 字重 | **400** | **500** |
| 字距 | **1px** | 0.24px |
| 颜色 | `gold-muted` | `#9aa1ae` |
| 大小写 | `uppercase` | none |

来源：`workbench.css:148-153` + `workbench.css:1168-1174`（后者注释直言
"需在上一段之后重新声明以保持优先级"）vs `cinema.module.css:154-157` + `workbench.css:1157-1163`。

问题：
1. **`uppercase` 对中文无效**，但 `letter-spacing: 1px` 生效 — "故事梗概"四个字被拉散，
   与右栏 0.24px 的紧凑排版对不齐（截图中肉眼可见左侧标签更"松"）。
2. 字重 400 vs 500，左侧标签更轻，辅助信息的层级反而比正文弱。
3. 这是"为了英文标签设计顺手套到中文上"的典型痕迹。

**修**：删掉 `text-transform:uppercase`，`letter-spacing` 降到 `0.24px`，
字重统一 500，保留金色作为"文稿区"与"设定区"的语义区分即可。

---

### P1-2 文稿区 label 聚焦不变色，设定区会变

`workbench.css:1164-1166` 定义了 `:focus-within > span { color: gold }`，
但 `workbench.css:1168-1174` 在其后把文稿区 label 重新声明为 `gold-muted` — 
**结果是右栏输入框聚焦时标签变金，左栏永远不变。**

看 `shots/06-focus.png`：光标在梗概里，"故事梗概"标签是暗金色；切到右栏画幅，
"画幅"标签会变亮金。同一交互在两栏反馈不同，这是明确的系统性问题。

**修**：文稿区聚焦用别的方式表达（加深文字色 / 下边线加粗 / 标签变主文字色），
不要靠覆盖掉全局聚焦反馈来实现。

---

### P1-3 段落编号与文本错位，且随段落高度漂移

`workbench.css:1022-1032` 用硬编码 `padding-top: 34px` 让 `01` 对齐首行。
但 textarea 是 `field-sizing:content`，高度随内容变化（实测 66px / 89px 两种）。实测对齐量：

| 段落 | textarea 高 | 编号相对框顶 | 编号中心 − 框中心 |
| --- | --- | --- | --- |
| 段落 1 | 66px | −27px | **−33px** |
| 段落 2 | 66px | −27px | −33px |
| 段落 3 | 66px | −27px | −33px |
| 段落 4 | 89px | −27px | **−45px** |

段落 4 比段落 1 多偏 12px。截图中 `03-scrolled-bottom.png` 的 `04` 明显比 `01` 更脱离文本块。
**修**：改为 flex 布局 + `align-items: baseline`，或用 `margin-top: auto` 随盒高自适应。

---

### P1-4 右栏底部 114px 空白

左栏 1017px / 右栏盒 1017px（grid 拉伸对齐），但右栏**实际内容只到 903px**。
底部 114px 是纯空白，视觉上右栏像"没写完"。

**修**：右栏加 `position: sticky; top: 24px` + `align-self: start`，
让它在长文稿滚动时跟随，也顺带解决右栏"跟着长文稿滚出去"的问题。

---

### P1-5 1440 宽下右栏几乎贴边

`cinema.module.css:387-390` 把 `max-width` 从 workbench 的 `1240px` 改成 `none`，实测：

| 视口 | 左栏宽 | 右栏起点 | 右栏宽 | 右侧留白 |
| --- | --- | --- | --- | --- |
| 1440 | 773px | 1047px | 360px | **33px** |
| 1080 | 515px | 753px | 300px | 27px |

1440 下左栏 773px、右栏 360px、右侧只剩 33px 留白，而左侧是 244px。
**视觉重心整体偏左，且右栏贴着窗口边缘**（DESIGN.md 的参考分辨率是 1440×1000）。

**修**：保留 `max-width: 1240px` 或改为 `1440px`，两侧留白对称。
