# CineAI Studio 设计规范 v2

本文是 CineAI Studio 前端重设计的唯一设计契约，用于喂给 Google Stitch 生成
新一版界面，也用于约束落地实现。它在 v1 的基础上**深化而非推翻**：保留暗色
电影感、暖金操作色、紫色 AI 语义与左侧流程导航，重点解决**可读性、信息层级、
术语外泄与状态表达**四类问题。

v1 规范见仓库根目录 `DESIGN.md`，它描述的是当前已实现的界面，作为历史记录保留。
本文落地实现后，应替换根部 `DESIGN.md`，保持仓库只有一份生效规范。

## 一、本次改造的目标与边界

### 1.1 四个必须解决的问题

按优先级排序。第 1 条是本次重设计的最高优先级，其余都是它的衍生。

**1. 字号过小，可读性不达标。** 当前 `src/app/globals.css` 共 385 处
`font-size` 声明，其中 **316 处（82%）小于等于 12px，207 处（47%）小于等于
10px**，最小到 6px。`src/features/creative/workbench.css` 只有 52 处声明且最低
11px，本身是健康的，但覆盖不全，因此新流程大量文字仍继承旧样式的小字号。
界面上真正的正文按 10px 渲染，这是"看起来丑、读起来累"的第一位原因，也直接
违反无障碍基线。v2 必须建立统一的排版阶梯，并把 11px 设为**任何文字的绝对下限**。

**2. 信息层级不清。** 分镜卡片单卡同时承载序号、时长、景别、人物标签、三个
就绪维度和悬停操作，在约 430px 宽的栏内没有主次。面板内同级元素过多，用户
找不到"下一步该做什么"。

**3. 术语与计量单位不统一。** 费用估算用人民币（`预计 ¥X.XX`），而视频生成
弹窗用虚拟积分（`可用 X 积分 · 已预留 Y 积分`）。同一产品两套价值单位，用户无法
心算。"技术详情"折叠区的内容保留是正确设计，但折叠区之外不允许再出现实现细节。

**4. 状态表达不完整。** 生成中、已过期、部分就绪、失败重试等状态缺少统一的
骨架屏、百分比与就近解释，用户会误判"按钮坏了"。详见第八章。

### 1.2 v1 已修复项，本次不要重复修

经核对当前代码，v1 审计报告中的以下问题**已经解决**，重设计时不要把它们当作
待修项，否则会做出无意义的改动：

| 审计原结论 | 当前实际状态 |
| --- | --- |
| 暖金存在 `--cw-gold: #e2bd75` 与 `#F5B942` 混色 | 已统一：`--cw-gold: var(--gold)`（`globals.css:13`） |
| 环境素材阶段无编号、不推进、进度只到 `/3` | 已修复：五阶段 `01`–`05` 全部编号，进度为 `/ 5 阶段已确认`（`StageNavigation.tsx:8-14`） |
| 检视面板 5 个生成按钮平铺 | 已修复：已按 `画面` / `声音` 分组，次要操作进入 `<details>`（`Creative.tsx:661-665`） |
| 技术详情散落多处 | 已统一为 `TechnicalDetails` 组件，默认折叠 |
| 导出确认静默失败 | 已有覆盖率进度与就近说明，达到 95% 才可保存验收 |
| `workbench.css` 使用 `:has()` 劫持布局 | 已全部移除 |

### 1.3 视觉语言不改变

保持 v1 的定位：**专业剪辑工作台**。密集、克制、无装饰。金色只表示用户主动
操作，紫色只表示 AI 生成入口。不引入玻璃拟态、霓虹光晕、渐变背景、emoji 图标或
自定义鼠标。层级依靠字号、字重、留白与描边建立，不依靠阴影堆叠。

## 二、色彩系统

沿用 v1 调色板，不新增色相。右列为 Stitch 输出的 Material 3 令牌名，落地时
按此表映射，**不要直接使用 M3 令牌名写业务样式**。

| 语义 | 值 | M3 令牌 | 使用范围 |
| --- | --- | --- | --- |
| 画布 | `#0E0F13` | `background` / `surface-dim` | 全局页面底 |
| 面板 | `#16181F` | `surface` | 面板、卡片 |
| 浮层 | `#1E2129` | `surface-container` | 输入框、下拉、弹窗 |
| 结构边界 | `#2A2E38` | `outline-variant` | 分隔线、卡片描边 |
| 主文字 | `#F2F3F5` | `on-surface` | 标题与正文 |
| 次要文字 | `#9298A5` | `on-surface-variant` | 说明、辅助信息 |
| 弱化文字 | `#5C6370` | `outline` | 禁用态、占位 |
| 电影暖金 | `#F5B942` | `primary` / `primary-container` | 主按钮、选中、时间轴游标 |
| AI 柔紫 | `#A293EE` | `secondary` | AI 生成入口、候选标识 |
| 完成绿 | `#75C9A1` | `tertiary` | 完成、已确认 |
| 失败红 | `#EF8385` | `error` | 错误、删除、失败 |

规则：

- 正文文字对比度不低于 4.5:1；`#9298A5` 只能用于 13px 及以上的次要文字，
  11px–12px 的标签改用 `#F2F3F5` 以保证对比度。
- 金色**不得**用于纯装饰。它出现在哪里，就意味着"这里可以点"或"这里是当前项"。
- 状态永远同时用图标与文字表达，不允许只用颜色区分。
- 新增颜色需先补入本表，并给出 M3 映射，否则不予采纳。

## 三、字体与排版阶梯

### 3.1 字体选择

界面的主体是中文，这一点决定了字体的取舍：**Stitch 的字体枚举里没有任何 CJK
字体**，`INTER`、`SORA`、`GEIST` 等均不含中文字形。因此中文最终仍由系统字体
渲染，字体选择实际只影响拉丁字母、数字与标点。

- **中文**：保持系统栈 `PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`。
- **拉丁、标题、数字**：`GEIST`（若 Stitch 侧需备选，用 `SORA`）。
- **时间码、时长、序号、坐标**：`JETBRAINS_MONO` 或 `GOOGLE_SANS_MONO`。

v1 规范中"无需在线字体服务即可打开应用"的约束必须保持，因此新增字体一律通过
`next/font` 自托管，不使用 `<link>` 引 CDN，也不依赖运行时联网。

### 3.2 排版阶梯

这是本次重设计最重要的产出。当前项目缺少排版阶梯，导致逐处手写字号。v2 只允许
以下八个档位，**任何新样式必须从表中取用，不允许自造中间值**。

| 令牌 | 字号 / 行高 | 字重 | 用途 | 约束 |
| --- | --- | --- | --- | --- |
| `display` | 30 / 38 | 600 | 首页主标题、项目名大标题 | 每屏最多 1 处 |
| `title-1` | 22 / 30 | 600 | 阶段标题、页面级标题 | 每面板 1 处 |
| `title-2` | 17 / 24 | 600 | 卡片标题、弹窗标题、分镜标题 | — |
| `body` | 14 / 22 | 400 | **正文基准，所有可读正文的下限** | 面板内正文默认值 |
| `body-sm` | 13 / 20 | 400 | 面板内次要说明、字段值 | 不得用于主要信息 |
| `label` | 12 / 16 | 500 | 表单标签、表头、状态文字 | 不得承载长句 |
| `caption` | 11 / 16 | 500 | 徽标、计数、单位 | **绝对下限，不得再小** |
| `mono` | 13 / 18 | 500 | 时间码、时长、序号 | 仅数字与时间码 |

硬性规则：

1. **禁止出现 10px 及以下字号。** 改造时必须删除 `6px / 7px / 8px / 9px / 10px`
   档位，把对应元素改用 `caption` 或 `label`。若删档后布局放不下，说明该处信息
   本身过载，应减少信息而不是缩小字号。
2. 正文行高保持在 1.5–1.75。单行文字长度控制在 65–75 个字符以内。
3. 主标题与正文通过字重（600 对 400）和字号建立对比，不通过颜色明暗。
4. 数字与时间码必须使用等宽字体并右对齐，避免播放时宽度跳动。

## 四、间距、栅格与骨架

- 间距基准 4px，只允许 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56` 九档。
- 全局顶栏 64px，左侧导航 216px（可折叠为 56px）。
- 分镜工作台三栏：

当前实现（`globals.css:5036, 5141-5143, 5153-5157`）与 v2 目标对比如下。当前有
四种折叠组合（左收 / 右收 / 双收 / 全展开）各自硬编码列宽，v2 收敛为两个断点。

| 视口宽度 | 当前 | v2 目标（大纲 / 中栏 / 检视） |
| --- | --- | --- |
| ≥ 1700px | 240 / 自适应 / 330 | 240 / 自适应 / 330 |
| 1201–1699px | 210 / 自适应 / 300 | 210 / 自适应 / 300 |
| 1024–1200px | 170 / 自适应 / 270，分镜卡单列 | 176 / 自适应 / 280，分镜卡保持双列 |
| < 1024px | ≤800 才堆叠；801–1200 仍是三栏 | 直接堆叠：大纲收进抽屉，检视栏贴底 |
| 折叠态 | 42px，四种组合分别硬编码 | 统一 44px，组合由 CSS 变量推导 |

- 底部时间轴固定 96px（当前 102px，`globals.css:5110`），允许局部横向滚动，
  页面本身不得横向溢出。时间轴在 1200px 以下不得隐藏镜头标签。
- 断点收敛为三个：`1700`、`1200`、`1024`。当前样式表分散在 8 个断点
  （1700/1200/999/900/800/760/650/520），必须合并。

## 五、圆角、描边与层级

- 圆角：输入框与徽标 6px，按钮 8px，卡片与面板 12px，弹窗 16px。
  相较 v1 的 7/9/13px 略微放大，用于缓解工具感带来的压迫。
- 描边：默认 1px `#2A2E38`；选中态 1px 金色；AI 入口 1px 紫色。
- 阴影只保留一档（`0 8px 24px rgba(0,0,0,.35)`），仅用于弹窗与浮层。
  卡片不使用阴影，靠描边区分。
- z-index 只允许 `10 / 20 / 30 / 50 / 100` 五档，分别对应粘性元素、下拉、
  侧栏浮层、弹窗、通知与 toast。

## 六、组件规范

所有组件必须定义完整状态：默认、悬停、聚焦、按下、禁用、加载中、错误。

| 组件 | 规格与状态要求 |
| --- | --- |
| 主按钮 | 金色渐变，`label` 字重 500，高 36px（紧凑 30px）。异步操作时必须进入加载态：禁用 + 加载指示 + 文案改为进行式（如"生成中…"），禁止只转圈不改文案 |
| 次按钮 | 透明底 + 描边，悬停变 `surface-container` |
| AI 按钮 | 紫色描边 + 紫色图标，表示会触发模型调用而非本地操作 |
| 危险按钮 | 红色文字，仅删除与取消使用，需要二次确认 |
| 图标按钮 | 24×24 viewBox，实际尺寸只允许 14/16/18/20px；必须带 `aria-label`；命中区不小于 32×32，触屏不小于 44×44 |
| 分镜卡片 | 固定槽位顺序：缩略图 → 序号 + 时长 → 标题 → 景别/人物标签 → 三个就绪点。卡片高度必须固定，加载与悬停不得引起布局位移 |
| 状态徽标 | 图标 + 文字成对出现，禁止纯色圆点 |
| 阶段导航 | 五阶段固定编号 `01`–`05`，每项显示标题与状态（已确认 / 待确认 / 当前）。当前项用金色下边框，不使用背景填充 |
| 表单字段 | 标签在上方，必填有标记，辅助说明在下方，错误就近显示且带 `role="alert"` |
| 弹窗 | 使用原生 `dialog`，支持焦点约束、Escape 与遮罩关闭；标题为一句用户语言，禁止出现供应商或模型名 |
| 空状态 | 图标 + 标题 + 一句说明 + 一个主操作。当前空态已达标，保持该结构 |
| 骨架屏 | 首屏恢复与批量生成必须使用骨架屏或确定性进度条，禁止只显示一行文字 |
| 进度条 | 批量生成必须有百分比；无百分比时使用不确定态动画而非静态文字 |
| 时间轴 | 分镜缩略图 + 时长 + 选中金色游标；仅支持首尾淡化，不得画出转场库或多轨编辑器 |

## 七、术语与文案纪律

界面上只允许出现创作者语言。下表左列一律**禁止出现在折叠的"技术详情"之外**。

| 禁止出现 | 替换为 |
| --- | --- |
| `task_id` / `source_task_id` / `providerTaskId` / 远端任务 ID | 折叠进技术详情；正文只说"生成任务" |
| `parent_revision` / 父版本哈希 | 折叠进技术详情 |
| `expected` / 版本门禁 / 409 | "内容已更新，请重新确认" |
| `nonce` / 申请编号 | 移除，不展示 |
| `entityId` / 角色编号 / 版本号 | 只显示角色名 |
| `stale` / `已过期` | "素材已过期，需重新生成" |
| 供应商与模型名（MiniMax、H3、`mimo-v2.5-*`、GPT Image） | 折叠进技术详情 |
| `asset_id` / `voice_id` / JSON 原文 | 只允许出现在技术详情折叠区 |
| `并发上限 2` | "同时最多生成 2 个镜头" |
| 积分 | **统一为人民币**，`预计 ¥X.XX，实际以服务商结算为准` |
| `降级原因` | "部分参考图未生效，已用文字描述补足" |

计量单位统一是硬要求：全产品只保留人民币一种价值单位。若积分是真实产品机制，
必须在首次出现处给出一次性换算说明，且不得与人民币在同一层级混用。

专业透明度（费用预估、失败不静默重试、额度上限）必须保留，但措辞需按上表改写。
文案字典统一收敛到 `src/features/creative/copy.ts`，新文案先入字典再使用。

## 八、状态体系

所有异步结果必须能落入下表之一，且每个状态都要有**非颜色的**区分手段与就近解释。

| 状态 | 视觉 | 文案 | 可用操作 |
| --- | --- | --- | --- |
| 未生成 | 虚线描边占位 | 尚无画面 | 生成 |
| 生成中 | 骨架屏 + 进度 | 生成中 45% | 取消 |
| 已生成待选用 | 紫色候选角标 | 有 2 个候选待选用 | 查看候选、选用 |
| 已选用 | 实线描边 | 已选用 | 重新生成 |
| 已过期待更新 | 金色描边 + 警示图标 | 素材已过期，需重新生成 | 重新生成 |
| 部分就绪 | 就绪点逐项显示 | 画面就绪，声音待生成 | 补齐缺失项 |
| 失败 | 红色描边 + 错误图标 | 生成失败，可重试 | 重试、查看技术详情 |

关键原则：**"已过期"与"未生成"必须在视觉上明显不同**，二者当前容易混淆；
"部分就绪"不得用单一图标概括，三个维度要分别可见。

## 九、图标与素材

- 图标统一使用 `lucide-react`，24×24 viewBox。
- **Stitch 默认输出 Material Symbols 图标与 emoji，必须在生成提示中明确禁止**，
  并要求描边风格图标。常用对照：画面 → `Image`，声音 → `Volume2`，时间/时长 →
  `Clock`，导出 → `Download`，3D → `Box`，队列 → `ListVideo`，角色 → `UsersRound`，
  AI 生成 → `Sparkles`，确认 → `Check`，过期 → `AlertTriangle`。
- 封面与头像沿用 `public/assets/`，运行时不引外链图片。所有图片需有 `alt`。
- 不使用 emoji 作为界面图标。

## 十、动效

- 微交互 150ms，面板展开收起 220ms，缓动为 ease-out。
- 只对 `transform` 与 `opacity` 做动画，避免动画 `width` / `height`。
- 遵守 `prefers-reduced-motion`，在该模式下关闭位移与淡入。
- 不使用持续闪烁、循环扫光、大范围光晕或自定义鼠标。

## 十一、无障碍

- 正文对比度不低于 4.5:1。
- 所有可交互元素可见 `focus-visible` 描边：2px 金色，偏移 2px。
- 图标按钮必须有 `aria-label`；表单控件必须有 `<label for>`。
- 状态不得只依赖颜色；错误信息使用 `role="alert"`。
- Tab 顺序与视觉顺序一致；弹窗打开时焦点被约束在弹窗内。

## 十二、响应式

- 以桌面优先，参考分辨率 1440×1000 与 1920×1080。
- 小于 900px 时显示"建议使用桌面端获得完整体验"提示，并允许继续使用。
- 首页、新建向导、导出页在窄屏切换为单列。
- 分镜工作台在窄屏改为上下堆叠，检视面板贴底，时间轴吸底。
- 任何视口下页面都不得横向溢出。

## 十三、Stitch 生成约束

生成新界面时必须遵守，否则产出无法落地：

1. 设备类型一律 `DESKTOP`，画布 `1440×1000`，同时说明 1920 宽下的自适应行为。
2. 一次只生成一个屏幕，不要在一个提示里要求多个页面。
3. 使用真实中文文案，禁止 `lorem ipsum`、禁止占位英文。
4. 禁止 Material Symbols 与 emoji，使用描边风格图标。
5. 禁止玻璃拟态、霓虹、渐变背景、悬浮装饰、大圆角胶囊化。
6. 必须显式画出空态、加载态与一种错误或过期态，不能只画理想态。
7. 所有字号必须落在第三章的八档阶梯内，最小 11px。
8. 金紫语义不得互换：金色 = 用户操作，紫色 = AI 生成。

## 十四、明确边界

以下能力当前代码并不支持，设计稿中**不得画出对应的可操作控件**，避免做出
无法兑现的承诺：

- 口型同步（lip-sync）尚未实现。
- 无分集 / 多集结构，只有单条短片。
- 时间轴无转场库、无多轨编辑、无变速，仅支持首尾淡化。
- 无自动视觉一致性审核，一致性依赖人工验收。
- 无项目导入入口，只有导出。
- 浏览器内只能导出无声 WebM，MP4 与真实混音需要后端。
- 不展示 GPU 在线率、模型供应商、成本或营收等无真实数据支撑的指标。
